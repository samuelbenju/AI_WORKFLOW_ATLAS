## Búsqueda futura sin bloquear lanzamiento

Con 65 fichas/30 guías, conservar la búsqueda PostgreSQL actual rápida y gratuita. Primero observar consultas solo mediante un mecanismo aprobado que evite PII; no activar almacenamiento de términos por esta propuesta. Evaluar tokenización, sinónimos editoriales y relevancia con un corpus pequeño etiquetado, sin servicios externos. Full-text `tsvector`/GIN o trigramas requieren diseño/medición y, si corresponde, migración futura expresamente autorizada; no modificar ahora las 16 migraciones. Una búsqueda híbrida con embeddings/LLM solo después de presupuesto, API key autorizada, límites y evidencia de mejora. No activar IA para recomendar enlaces del catálogo.

## Criterio de entrega y orden de publicación

Cada semana tiene como máximo dos propuestas, no una obligación de publicar dos textos. Si faltan fuentes, tiempo de revisión o prueba reproducible, mantener el borrador y mover la fecha. Para las primeras semanas reutilizar/revisar los seis DRAFT cuando coincida la intención; evitar un segundo artículo que compita con el mismo recurso. El cuadro de mejoras individuales está en SEO_STRATEGY.md.

Antes de publicar: una pregunta concreta, valor añadido distinto de la ficha/guía, fuentes y fechas revisadas, ejemplo etiquetado correctamente, enlaces internos comprobados, título/descripción propios, autor/revisor aprobado, accesibilidad y vista móvil. Registrar después el slug publicado y observar ventanas completas de datos reales, sin umbrales de tráfico inventados. Nunca activar envío de newsletter, agentes o generación de modelos para cumplir el calendario.
